# 输入格式说明 —— 设计表 / 意图 spec

> 本文定义 HarnessPCB 的两类设计输入：**设计表**（design.json，喂给 `d2s`
> 全链的唯一输入）与**放置意图 spec**（intent.json，喂给 `plr place
> --intent-file` 的可选输入）。合成范例：`demo/demo_blinker.design.json` +
> `demo/demo_blinker_intent.json`；真实工程范例：
> `executors/SchematicDesign/design2schematic/templates/usb2rs485.design.json`。

---

## 一、设计表 design.json

一个 JSON 文件描述一块板：器件清单、每个引脚连什么网、板框尺寸、锚点。
`d2s` 由它生成原理图（ERC 门）→ 板骨架 → 放置 → 布线 → 铺铜 → DRC 全链。

### 1. 顶层九键

| 键 | 必填 | 内容 |
|----|------|------|
| `$schema_note` | 否 | 自由文本备注（不参与生成） |
| `project` | 是 | `{name, title, spec}`；name = 大写工程名（版本文件名前缀），title 进原理图标题栏，spec 自由描述 |
| `board` | 是 | `{width, height, layers, mounting_holes, hole_d, hole_edge_offset}`（mm；layers 目前固定 2）；可选 `full_pads`（见 §5） |
| `parts` | 是 | 器件数组 `[{ref, lib, value, footprint, x, y}]`；lib/footprint 用 KiCad 标准库全名（`库:符号名` / `库:封装名`） |
| `conns` | 是 | 连接数组 `[{ref, pin, net}]`——**每个引脚连哪个网**，是设计的核心 |
| `power` | 是 | `{rails: [...], pwr_flags: [...]}`；rails = 电源网名表（备注性质）；pwr_flags = PWR_FLAG 条目，见 §7 |
| `no_connect` | 否 | 显式 NC（一般不需要，见 §4 自动 NC） |
| `keep_connected` | 否 | 引脚名表；这些引脚即使没在 conns 里出现也不打 NC 标（配合自动 NC） |
| `anchors` | 否 | `[{ref, x, y, rotation}]`——板坐标预放（生成板骨架时钉住），mm |

### 2. `parts` 的 x/y 是**原理图图纸坐标**

只决定符号画在原理图哪里（布局美观用），与 PCB 放置无关。PCB 放置由
`plr place` 的 sch 驱动算法 + `anchors` + 意图 spec 决定。经验：U1 主控
放图纸中部，外围器件按功能环绕，连接器放图纸左右远端。

### 3. 引脚命名规则（conns.pin）

| 器件 | 引脚名 |
|------|--------|
| 连接器 / 电阻 / 电容 / 电感 / 晶振等无源件 | 数字 `"1"` `"2"` … |
| LED | `"A"` / `"K"` |
| MCU / IC | 符号库里的端口名（如 STM32 的 `"PA0"` `"PC13"` `"NRST"` `"BOOT0"` `"VDD"` `"VSS"`） |

**重复电源引脚要加 `"multi": true`**：STM32F103 有 3 个 VDD，conns 里
`{"ref":"U1","pin":"VDD","net":"+3V3","multi":true}` 才会覆盖全部同名引脚；
漏掉 multi 时只连第一枚，其余会报 ERC「Pin not connected」（本包 demo 调试
实测踩过）。

不确定引脚名时，用包内工具查：
`<包根>/executors/Placement/.venv/bin/plr`（或 kca）相关 inspect 命令，
或直接翻 KiCad 安装目录的符号库 `.kicad_sym`（`Device:R` 等）。

### 4. 自动 no-connect（重要）

未在 conns 出现、也不在 `keep_connected` 里的引脚**自动打 NC 标**（ERC
不报悬空）。所以 MCU 用不着的 GPIO 不用写任何条目。反向用法：
`keep_connected` 列出「现在不连、将来要连」的引脚名，避免被打 NC。
单条显式 NC：conns 里 `{"ref": "U1", "pin": "PB5", "net": null}`。

### 5. `board.full_pads`（可选）

铺铜步（pour）默认热焊盘连接；列在此数组的器件 ref 改为**实连焊盘**
（大电流路径如电源输入端子、LDO）。不列则全部热焊盘。

### 6. `anchors` 旋转约定

0°=不转；左边缘件 90°、右边缘件 270°、上边缘件 180°（开口朝外惯例）。
anchors 只钉位置/朝向，开口朝外的三级信号推断由意图 spec（见二）接管更准。

### 7. `power.pwr_flags`（电源轨驱动声明）

ERC 要求每条电源轨上至少一个 power_out 引脚。三种情况：

| 轨的驱动情况 | 处理 |
|------|------|
| 轨上有天然 power_out（LDO 的 VO、USB 连接器 VBUS） | 不加条目 |
| 轨只被被动件/power_in 占据（典型：+5V 输入轨、GND） | 加 PWR_FLAG 条目 |
| 已有 power_out 还加 PWR_FLAG | ERC 报 power_out ×2 冲突——别加 |

条目格式 `{"ref": "F1", "x": 45.72, "y": 88.9, "net": "+5V"}`：x/y 是原理图
图纸坐标（找个空位即可，只影响 ERC/网表，不影响 PCB）；net = 要驱动的轨名。
症状对照：漏写时 ERC 报 N 条「Input Power pin not driven by any Output
Power pins」（N = 该轨 power_in 引脚数）。

## 二、放置意图 spec intent.json

`plr place --intent-file <spec.json>`（可选输入；不给则纯 sch 驱动放置）。
作用：把「哪个接口件在哪条边、开口朝外、凸出多少」写成显式设计输入，
**位姿由引擎从封装几何算出**，不是抄坐标。

```json
{
  "protrude_mm": 1.0,
  "pad_clear_mm": 0.3,
  "min_gap_mm": 0.25,
  "obstacle_band_mm": 12.0,
  "items": {
    "J1": {"edge": "left", "along": 0.5},
    "J2": {"edge": "right", "along": 0.5}
  },
  "power_cluster": {"anchor": "J1", "depth_mm": 15.0, "margin_mm": 6.0, "gap_mm": 1.0}
}
```

- **items**：`edge` = top/bottom/left/right（板边）；`along` ∈ [0,1] = 外框
  中心沿边比例位置（0=左/上端）；可选 `rot` 显式覆盖朝向（缺省走三级
  信号：焊盘质心 → 模板贴边推断 → 模板朝向，如实上报）。
- **凸出钳位**：`protrude_mm` 外框外沿凸出板边量；焊盘至少 `pad_clear_mm`
  留在板内，余量不足时自动钳小。
- 同边意图件互推开 `min_gap_mm`；`obstacle_band_mm` 带内固定障碍（安装孔）参与避让。
- **power_cluster**（可选）：电源元器件聚集到锚端子朝板内一侧的矩形带
  （depth=纵深 / margin=切向外扩 / gap=间隙）。成员三层自动判定：电源
  变换 IC 强锚、纯电源被动件（防反二极管/电感）跟进、去耦电容走投影
  分支不整板乱拽。

## 三、版本命名与产物

- 每次全链生成 `<project.name>_v<N>.*`（N = 项目目录内最大号 +1）：
  `DEMO_BLINKER_v1.kicad_sch` / `_v1_base.kicad_pcb`（板骨架）/
  `_v1_stackup.json`（自动生成：2 层 + 过孔梯子 0.3 孔/0.6 外径）/
  `_v1_placed.kicad_pcb` / `_v1_routed/`（结果 JSON 里 `final` 指向选定
  板）/ `_v1_poured.kicad_pcb` / DRC 报告。
- `d2s chain --step-from {sch,board,place,route,drc}` 从某步重入（复用
  既有产物）；重入默认复用最新版本号，`--step-from sch` 默认开新号。

## 四、验证门（自动把着）

1. **ERC 门**：sch 步生成后自动跑 ERC，0 错才放行（`--no-erc-gate` 可跳
   过，不建议）；逐 pin 回读对账（设计表 conns vs 原理图网络）。
2. **布线完成度**：route 步按 clearance 阶梯（µm，如 `205,215,225,235,245`）
   逐档尝试，全通即停；结果 JSON 的 `final` = 选定板。
3. **DRC 铜级 0**：铺铜后 DRC，铜级（短路/间距/阻焊桥/孔距/线宽/悬空
   过孔/未连接）须 0；丝印/库级残留见 skills/pcb-drc-read 的分类口径。
